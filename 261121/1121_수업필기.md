## 2. 임베디드 통신 프로토콜

센서와 MCU, 또는 MCU끼리 데이터를 주고받을 때 사용한다. (예: IMU → MCU, MCU ↔ MCU)

| 구분 | 설명 |
| --- | --- |
| **동기 (Synchronous)** | 클럭(clock) 신호로 송수신 타이밍을 맞춰서 통신 |
| **비동기 (Asynchronous)** | 클럭 없이 미리 약속한 전송 속도(Baud rate)와 프레임 형식으로 통신 |

### UART (비동기 직렬)
- 선 2개: **TX**(Transmit, 송신) ↔ **RX**(Receive, 수신)를 **서로 엇갈려** 연결
- 평소(Idle)에는 HIGH 상태 유지 (풀업)
- 전송 순서: **Start bit**(HIGH → LOW) → **Data bit**(8bit, LSB부터) → **Stop bit**(HIGH)

### I²C (동기 직렬)
- 선 2개: **SDA**(Serial Data, 데이터) + **SCL**(Serial Clock, 클럭)
- 시작 신호: SCL이 HIGH일 때 SDA를 HIGH → LOW로 내림
- SCL이 올라가는 순간마다 SDA의 데이터를 읽음
- 받는 쪽이 8bit마다 **ACK / NACK** 신호로 수신 여부를 응답
- 선 2개에 여러 장치를 주소로 구분해서 연결할 수 있음

## 3. ROS (Robot Operating System)

### 고수준 / 저수준 제어

| 구분 | 고수준 | 저수준 |
| --- | --- | --- |
| 작업 | 판단, 계획 | 직접 제어 |
| 연산량 | 높음 | 낮음 |
| 주요요소 | 연산량 | 실시간성 |
| HW | SBC | MCU |
| OS | Linux | RTOS |
| SW | ROS2 | firmware, micro-ROS |
| 언어 | Python, C++ | C, C++ |

### ROS란?
- 이름은 OS지만 실제 운영체제가 아니라 **소프트웨어 프레임워크**
- 하드웨어 추상화: 하드웨어가 달라도 같은 방식으로 다룰 수 있게 해 줌
- 프로세스 간 통신 지원

### ROS1 vs ROS2

| 구분 | ROS1 | ROS2 |
| --- | --- | --- |
| 통신 구조 | 중앙 집중 (Master 필수) | P2P (DDS 기반) |
| 통신 방식 | 자체 프로토콜 | DDS (산업 표준) |
| 보안 | 같은 네트워크에서 데이터 탈취 가능 | 보안 기능 지원 |
| 지원 OS | Linux | Linux, Windows, macOS |

### DDS (Data Distribution Service)
- 산업 표준으로 쓰이는 통신 표준. ROS2는 DDS 위에서 동작
- QoS 설정 가능
- **Domain ID**: 같은 Domain ID를 가진 노드끼리만 통신. 기본값 = 0
  - 같은 네트워크의 다른 사람과 섞이지 않게 각자 다른 번호를 사용
  - 설정: `export ROS_DOMAIN_ID=번호`

### QoS (Quality of Service)
노드끼리 데이터를 주고받을 때의 통신 규칙

| 항목 | 옵션 | 의미 |
| --- | --- | --- |
| **Reliability** (신뢰성) | Reliable | 데이터가 확실히 도착하도록 재전송 |
| | Best Effort | 재전송 없이 최선만 다함 (빠르지만 손실 가능) |
| **Durability** (지속성) | Volatile | 구독 전에 보낸 데이터는 받지 못함 |
| | Transient Local | 나중에 구독해도 이전 데이터를 받을 수 있음 |

## 4. ROS2 기본 용어

| 용어 | 설명 |
| --- | --- |
| **Node** | 하나의 실행 단위. 노드 1개 = 프로세스 1개 = 터미널 1개 |
| **Topic** | 데이터를 주고받는 통로(주제 이름). 예: `/chatter` |
| **Publish / Subscribe** | 토픽에 데이터 송신 / 토픽의 데이터 구독(수신) |
| **Message (msg type)** | 송신자와 구독자가 주고받는 데이터와 그 형식 |
| **Service** | 요청(Request)을 보내면 응답(Response)을 받는 1:1 통신 |

<br>

## 5. ROS2 명령어

명령어 형식: `ros2` + `카테고리` + `동사`
명령어 형식: `ros2` + `run` + `카테고리 이름`

| 명령어 | 기능 |
| --- | --- |
| `ros2 node list` | 실행 중인 노드 목록 |
| `ros2 topic list` | 현재 토픽 목록 |
| `ros2 topic echo /chatter` | `/chatter` 토픽의 메시지를 터미널에 출력 |
| `rqt_graph` | 노드와 토픽의 연결 관계를 그래프로 시각화 |

## 6. Colcon

ROS2 패키지를 빌드하는 도구. `colcon build`로 워크스페이스 안의 패키지를 한 번에 빌드한다.

### colcon 워크스페이스 구조

| 디렉토리 | 역할 |
| --- | --- |
| `src/` | 개발자가 작성한 ROS2 패키지 소스 코드 |
| `build/` | 빌드 중에 생기는 파일 (패키지별로 생성) |
| `install/` | 빌드 결과물(실행 파일, 라이브러리)과 환경 설정 스크립트(`setup.bash`) |
| `log/` | 빌드 기록과 오류 메시지 등 로그 |

### 패키지

빌드는 `/workspace`에서, 패키지 생성은 `/src`에서!!!!!!

| 파일 / 폴더 | 역할 |
| --- | --- |
| `패키지명/패키지명/` | 직접 작성하는 파이썬 노드 파일(.py)을 넣는 곳 |
| `setup.py` | 패키지 설치 설정. `entry_points`에 노드를 등록해야 실행 가능 |
| `package.xml` | 패키지 정보(이름, 버전, 작성자)와 의존성 목록 |
| `test/` | 코드 검사용 테스트 파일 |
